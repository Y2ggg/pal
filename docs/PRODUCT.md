# 产品范围与理念

PAL（Personal Ability Library）是一套个人能力库。它希望把反复积累的经验变为可整理、可打磨、
可复用的能力，让这些能力拥有稳定的归处，也能在不同 Agent CLI 中继续使用。

长期方向是沉淀通用结构件，再结合规则与语义形成新的能力。当前版本先解决 Skill 的创建、
管理和跨 CLI 使用，不声称已经具备自动提炼、自动组合或效果评价能力。

## 当前范围：0.3.0

| 环节 | 已提供的能力 | 边界 |
|---|---|---|
| 创建与更新 | 在普通 Claude Code/Codex 会话中调用系统创建入口，按库规范生成完整 Skill | 一次覆盖两端，共享或定向适配；只写开发态 |
| 发布 | 将明确选中的 Skill 开发内容保存为生产内容 | 不自动安装，不把其他 Skill 的修改带入 |
| 挂载与使用 | 将所选生产内容安装到两端，使用稳定调用名 | 显式同步，新会话生效；不要求通过专用 runner |
| 管理 | Web 三层对照、概览、文件目录、发布/同步/卸载/删除/放弃修改 | 不在 Web 中创建或执行 Skill |
| 维护 | 内容校验、真实安装监测、系统入口更新、安装修复和中断恢复 | 完整性与安装健康不等于业务效果 |

当前只管理 Skill 组件，支持随附脚本、参考文件、模板、二进制资源。两端协议兼容时共享产物，
确有差异时生成定向产物。当前格式为基本 Skill 及 Claude 的 `model` 定向格式，
不等于支持全部原生扩展字段或任意第三方 Skill 原样导入，具体限制见[使用手册](USER-GUIDE.md)。
任何 CLI 的私有插件目录都只是消费副本，不是库的事实源。

## 三层需要明确推进

```text
开发库：修改中的内容
  │ 手动发布
  ▼
生产库：保存已确认的内容
  │ 手动同步
  ▼
CLI 挂载库：新会话实际发现的内容
```

开发修改不污染生产；发布不等于 CLI 已更新。用户可以明确要求连续发布并同步。
单项操作只影响选中的 Skill，全库同步要明确范围。主动卸载保留生产，之后不会因重新发布
（包括“发布并同步”）或全库同步而被自动启用；恢复使用需明确重新挂载。
删除尚有挂载时保留待完成状态，确认卸载后退出列表。

## 尚未开放与有意保留

日常使用采集、效果分析、评分、因果归因、自动迭代延期；不能从文件读取、安装状态或历史
加载推断 Skill 被实际使用，也不能将旧受控记录包装为日常完整追踪。

用户快照列表、回收站、任意历史回退、批量发布已退出。内部不可变 release、旧记录读取和
故障恢复继续保留，以维护已交付数据的完整性。`launch`、`run` 等兼容命令不是日常使用前提。

## 追踪标识说明

源码/测试中的 PRD、ACC 和后续范围标识用于追踪建设过程。公开版本不要求读者获得其他仓库。
判断当前行为时以本文件和使用手册为准，历史约束由当前已确认的范围调整解释。

| 标识组 | 当前对应的约束 |
|---|---|
| PRD-P0、ACC-001 | 初始化库及开发/生产边界 |
| PRD-MOUNT、ACC-002/008/011 | 配置挂载服务创建；生产挂载服务消费；彼此分离 |
| PRD-CLI/SPEC/CREATE、ACC-003～006 | 双端创建、规范校验、共享与定向完整产物 |
| PRD-RELEASE、ACC-007 | 生产引用明确不可变内容 |
| PRD-USE-001、ACC-009 | 普通双端会话真实发现与使用 |
| PRD-USE-002、ACC-010、PRD-P3 | 日常记录与评价延期；保留旧受控数据兼容 |
| ACC-012 | 失败拒绝继续，不把部分完成报告为成功 |
| WEB/PSM/STG/SLC/MON/BRAND | 控制台、三层管理、逐项动作、安装监测与 PAL 品牌 |

未来改变这些边界需要先讨论具体差异并更新文档、实现和行为测试，不能将技术限制静默改写为
新的用户前提。
